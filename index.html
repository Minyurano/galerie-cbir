Le projet

Application Web de gestion d'une galerie de photos avec recherche d'images par le contenu (CBIR). Chaque image est décrite automatiquement par sa couleur et sa texture ; l'utilisateur recherche des images similaires à une image requête, puis affine les résultats par retour de pertinence.

Mini-projet du Master IASD (S3, 2026-2027), FST Tanger. Cette page est une version Web autonome (JavaScript) de l'application ; la version complète utilise Flask et une API Flask-RESTful.

  • Moments de couleur (9)

Descripteurs texture
  • GLCM / Haralick (4)
  • LBP (256)
Recherche
  • Recherche simple (distance pondérée normalisée)
  • Retour de pertinence : QVM, FRE, Re-weighting Type-1

Méthodes de retour de pertinence

D(q, I) = Σi Wi · di(q, I)
  1. QVM (Rocchio) : la requête est déplacée vers les images pertinentes et éloignée des non pertinentes : q' = αq + β·moy(R) − γ·moy(N).
  2. FRE : le poids d'un descripteur est l'inverse de sa dispersion parmi les images pertinentes (Wi ∝ 1/σi).
  3. Re-weighting Type-1 (méthode du groupe) : la requête devient la moyenne des images pertinentes ; chaque composante reçoit le poids Wi = (ε + σNr,i) / (ε + σrel,i) : fort si elle varie peu entre les images pertinentes mais beaucoup parmi les images retournées.

Résultats de l'application complète (GHIM-10K, 10 000 images)

400 requêtes (20 par classe), 25 images affichées, utilisateur simulé sans erreur. Précision@25 : 50,4 % en recherche simple, puis après 5 itérations 64,9 % avec QVM, 69,6 % avec FRE et 75,8 % avec Re-weighting Type-1 (test de Wilcoxon : p < 10-6 face aux deux autres).

Cette page est une version simplifiée qui tourne entièrement dans le navigateur (descripteurs recalculés en JavaScript, un poids par descripteur). Les chiffres de l'onglet Évaluation sont recalculés en direct sur les images de la galerie et diffèrent donc de ceux de l'application complète.
